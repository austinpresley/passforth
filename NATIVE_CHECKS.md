# Native Mac acceptance

Use the recipient's Mac and available native UI tools. Retain screenshots or accessibility state under `evidence/`; they must show the actual app, not a browser mockup. The shared client bundle identifier is in `CLIENT.json`; its private cache is scoped to the confirmed workspace project ID. Keep other installed apps and user work intact.

1. Open the installed signed Passforth release. Sign in to the recipient-owned Site through its sign-in window. Verify the native task list and verification task match the connected plugin. Verify the runtime workspace URL and project ID in its private verification export. Its Info.plist must contain no fixed workspace address and must use the public Passforth update feed.
2. Open the verification task generated by the live checker. Save the exact reference comment requested at its `reference` step. Verify no request was created. Generate the test attachment, upload it through the app and continue the checker to its private-file read. Download the file through the native save panel to a separate name and compare bytes with `cmp`. Preserve the live attachment ID for recovery.
3. Connect the owner's personal Dot as described in DOT_CONNECTION.md. Send the exact live-checker request through the native Send to Dot control. Read its actual acknowledgement and exact reply in the same native conversation. Continue the checker through `dot_reply`.
4. Read `evidence/mcp-session.json` for its nonce. Quit this test app normally. Launch its executable with `--offline-preview` to disable its background sync, keeping the machine's networking and security settings intact. Ensure only one copy of this workspace's app is running. Reuse a matching local test capture if resuming this step. Capture only once, titled exactly `Offline verification NONCE`, replacing NONCE with the session value. On the original verification task leave an unsent comment `UNSENT NONCE`. Keep it unsent throughout this test.
5. Quit and reopen the same executable with `--offline-preview`. Verify the captured task and unsent draft remain visible. Retain this offline restart evidence. Continue the checker's `offline_absent` read while the app remains offline; the server must still lack that capture.
6. Quit and reopen normally. Wait for a successful sync. Continue `offline_present`; the server must contain exactly one capture with paused status, unknown ownership and no check-in. Verify the outbox is empty and the draft is still unsent. Retain reconnected evidence. Clear only this test draft after verifying it.
7. Continue the live checker through cleanup and backup. Test records remain in history. Native title/task/checklist editing, note reading/writing, Daily Notes, linked notes, saved views, weekly blocks, keyboard search and global quick capture should render and operate using native controls. The regression suites cover their state rules; record any UI failure rather than assuming a compiling view works.

Complete `native-observations.json` using EVIDENCE.md after observing these outcomes. A machine without native UI access can finish server checks, but it cannot mark these native gates passed.
